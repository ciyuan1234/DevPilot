# 复盘 02：README 按企业标准补齐

> 日期：2026-08-12 ｜ 项目：DevPilot AI（MVP）
> 目标：把空 README 补齐为企业级项目入口文档

## 背景

项目初始化时 README 为空文件。企业标准认为 README 是项目的第一入口：决定新成员/协作者/面试官的第一印象，回答"这是什么、怎么跑、文档在哪、往哪走"。

## 过程：6 区块 + 2 轮决策

| 区块 | 内容 | 关键决策 |
|---|---|---|
| 1 | 项目介绍与定位 | 定位语直接复用 PRD 原句，保证文档间一致性；核心特性对应 MVP 范围 |
| 2 | 技术栈与架构 | 表格+文本分层图；明确"AI Gateway 不做 Agent 调度"的职责边界 |
| 3 | 快速开始 | **先实测后落文档**：删 build 目录从零构建+运行+curl 200 验证 |
| 4 | 项目结构 | 如实标注 frontend/agents/deploy 为"规划中"，不虚构 |
| 5 | 文档索引 | 表格化：PRD / SDD / 博客 / AGENTS.md 四个入口 |
| 6 | 路线图与边界 | V1 顺序（用户系统→…→CodeExplainAgent）+ 明确不做项 |

### 决策 1：语言
用户选择**中文**（与 PRD/SDD/博客一致），后续如需开源推广可加英文版。

### 决策 2：状态徽章
**暂不写** CI 徽章——现在没有 GitHub Actions，放徽章是"信息失真"（虚假绿色）。等 CI 配置好再补，符合"文档与事实一致"原则。

## 踩坑记录

1. **SDD 文件名带空格**：GitHub 链接必须写成 `docs/SDDv-%201.0.md`（`%20` 编码），普通写法会 404。
2. **`pgrep -f` 匹配 bash 自身**：清理后台进程时，`pgrep -f devpilot-backend` 会把正在执行的 `bash -c "...devpilot-backend..."` 也匹配上，看到"僵尸 PID"。解决：`pgrep -f 'build/devpilot-backend'` 精确匹配路径。
3. **PowerShell 变量转义**：`wsl -e bash -c "..."` 内用 `$(...)` 必须写成 `\$(...)`，否则在 Windows 侧先被解释（出现 `cat : 找不到路径` 假错误）。

## 复盘结论

1. **文档要可复现**：区块 3 亲身走了一遍从零构建，发现 CMake 配置阶段耗时明显（17s），但链路通畅——这就是"文档即测试"。
2. **诚实标注状态**："规划中"三个字防止 README 误导读者，比美化重要。
3. **微服务架构的关键单行**：README 架构层明确"AI Gateway 不做 Agent 调度"，这条职责边界写进公开文档后，后续实现（AI Gateway 模块）就不会跑偏。
4. **后续待办**：CI（GitHub Actions）+ 测试框架是下一个企业标准缺口，也是 README 里已留的坑位（徽章、"CI 与测试框架"待补项）。
